# Chess Kernel Development Roadmap

Этот документ описывает поэтапный план развития проекта Chess Kernel — абстрактного движка для настольных игр с поддержкой кастомных правил и топологий.

## 📋 Обзор этапов

| Этап | Название | Статус | Описание |
|------|----------|--------|----------|
| 0 | ✅ Ядро (Core) | **Завершено** | Абстрактное ядро с топологиями, состоянием и интерфейсами |
| 1 | ♟️ Стандартные шахматы | ⏳ В работе | RuleSet для классических шахмат (8×8) |
| 2 | 🖥️ Адаптеры | 📅 Запланировано | CLI, DOM, UCI протокол |
| 3 | 🎲 Кастомные правила | 📅 Запланировано | Crazyhouse, Chess960, Гексагональные шахматы |
| 4 | 🛠️ Инструменты | 📅 Запланировано | PGN/FEN, дерево ходов, валидатор |
| 5 | 🚀 Оптимизация | 📅 Будущее | Bitboards, tablebases, мультиплеер |

---

## 📍 Этап 0: Ядро (Core) — ✅ Завершено

**Цель:** Создать абстрактное, топология-агностик ядро без знаний о конкретных правилах игры.

### Реализованные компоненты:
- [x] Базовые типы (`Position`, `Coordinate`, `PlayerId`, `PieceType`)
- [x] Система направлений и перемещений (`Direction`, `Step`, `MovementPattern`)
- [x] Абстрактные фигуры (`PieceDefinition`) без логики ходов
- [x] Интерфейс `RuleSet` для подключения правил
- [x] Топологии: `RectangularTopology`, `HexagonalTopology`, `CustomTopology`
- [x] Неизменяемое состояние игры (`GameState`, `Move`, `MoveMetadata`)
- [x] Фабрика досок `createBoard()`
- [x] TypeScript декларации и сборка

**Результат:** Пакет `chess-kernel` готов к использованию.

📄 **Документация:** [Архитектура ядра](./architecture/core.md)

## 📍 Этап 1: Стандартные шахматы (Standard Chess RuleSet) — ⏳ В работе

**Цель:** Реализовать полный набор правил классических шахмат на основе ядра.

### Задачи:

#### 1.1 Создание пакета `rules-chess-standard`
- [ ] Инициализация npm пакета
- [ ] Настройка зависимостей от `chess-kernel`
- [ ] Определение констант (доска 8×8, игроки White/Black)

#### 1.2 Профили движения фигур
- [ ] Пешка: прямой ход, взятие по диагонали, начальный двойной шаг
- [ ] Ладья: ортогональные направления, любое расстояние
- [ ] Слон: диагональные направления, любое расстояние
- [ ] Конь: L-образные прыжки
- [ ] Ферзь: комбинация ладьи и слона
- [ ] Король: один шаг в любом направлении

#### 1.3 Специальные правила
- [ ] Рокировка (короткая и длинная)
  - [ ] Проверка прав на рокировку
  - [ ] Проверка пути (клетки между королем и ладьей)
  - [ ] Проверка шаха на пути короля
- [ ] Взятие на проходе (En Passant)
  - [ ] Отслеживание последнего хода пешки
  - [ ] Флаг `enPassantTarget` в состоянии
  - [ ] Специальный ход с флагом в `MoveMetadata`
- [ ] Превращение пешки (Promotion)
  - [ ] Обработка хода с флагом превращения
  - [ ] Выбор фигуры (Ферзь, Ладья, Слон, Конь)

#### 1.4 Валидация и состояние игры
- [ ] Метод `generatePseudoLegalMoves()`: генерация всех псевдо-легальных ходов
- [ ] Метод `isMoveLegal()`: проверка, не оставляет ли ход своего короля под шахом
- [ ] Метод `executeMove()`: применение хода с обновлением состояния
- [ ] Метод `getGameStatus()`: определение конца игры
  - [ ] Шах
  - [ ] Мат
  - [ ] Пат
  - [ ] Ничья (повторение позиций, правило 50 ходов, недостаток материала)

#### 1.5 Тестирование
- [ ] Юнит-тесты на движение каждой фигуры
- [ ] Тесты на специальные ходы (рокировка, en passant, promotion)
- [ ] Интеграционные тесты: прогон известных партий
- [ ] Тесты на краевые случаи (блокировка, связки, вскрытый шах)

**Критерии готовности:** Все тесты проходят, можно сыграть полную партию в CLI.

📄 **Документация:** [Правила стандартных шахмат](./architecture/ruleset-standard-chess.md)

## 📍 Этап 2: Адаптеры и Интерфейсы — 📅 Запланировано

**Цель:** Сделать игру видимой и управляемой без изменения ядра.

### Задачи:

#### 2.1 CLI Адаптер (Console UI)
- [ ] Текстовый рендер доски (ASCII/Unicode: ♔♕♖♗♘♙)
- [ ] Парсер ввода координат (e2e4, g1f3, O-O, O-O-O)
- [ ] Отображение статуса игры (шах, мат, чей ход)
- [ ] История ходов в консоли
- [ ] Команды: `new`, `undo`, `fen`, `help`, `quit`

#### 2.2 DOM/Web Адаптер
- [ ] HTML/CSS рендер доски (div-сетка или canvas)
- [ ] Обработчик кликов: выбор клетки, совершение хода
- [ ] Подсветка легальных ходов
- [ ] Drag & Drop для фигур (опционально)
- [ ] Пример интеграции с React/Vue (опционально)

#### 2.3 UCI Протокол (Universal Chess Interface)
- [ ] Парсер UCI команд (`position`, `go`, `stop`, `quit`, `ucinewgame`)
- [ ] Генератор UCI ответов (`bestmove`, `id`, `option`)
- [ ] Подключение к внешним GUI (Arena, CuteChess)
- [ ] Поддержка режима анализа (опционально)

**Критерии готовности:** Можно играть в консоли и браузере, подключиться к Stockfish.

📄 **Документация:** [Руководство по адаптерам](./architecture/adapters.md)

## 📍 Этап 3: Кастомные правила (Custom Rulesets) — 📅 Запланировано

**Цель:** Доказать гибкость архитектуры на примерах вариантов.

### Задачи:

#### 3.1 Crazyhouse (Шахматы с возвратом)
- [ ] Расширение `GameStateMetadata`: карманы (pockets) для каждого игрока
- [ ] Новый тип хода: `Drop` (сброс фигуры из кармана на пустую клетку)
- [ ] Изменение правила взятия: фигура уходит в карман, меняет цвет
- [ ] Ограничения: нельзя ставить пешку на 1/8 ряд, мат сброшенной пешкой
- [ ] Расширенный FEN для карманов

#### 3.2 Chess960 (Фишеровские шахматы)
- [ ] Генератор случайной начальной расстановки (960 позиций)
  - [ ] Слоны на разных цветах
  - [ ] Король между ладьями
- [ ] Адаптация рокировки под произвольные позиции ладей
- [ ] Поддержка стандартных и нестартандартных прав рокировки

#### 3.3 Гексагональные шахматы (Hex Chess)
- [ ] Использование `HexagonalTopology` из ядра
- [ ] Переопределение профилей движения под 6 направлений
  - [ ] Как ходит слон на гексах? (3 диагонали вместо 2)
  - [ ] Как ходит конь? (2 шага в любом направлении)
- [ ] Адаптация условий мата/пата
- [ ] Визуализация гексагональной доски (SVG/Canvas)

#### 3.4 Другие варианты (по желанию)
- [ ] Capablanca Chess (10×8, новые фигуры: архиепископ, канцлер)
- [ ] Шахматы на троих (3 игрока, специальная доска)
- [ ] Антимагические шахматы (Anti-Chess / Giveaway)

**Критерии готовности:** Минимум 2 работающих варианта помимо стандартных шахмат.

📄 **Документация:** [Создание собственного RuleSet](./architecture/custom-ruleset-guide.md)

### Задачи:

- [ ] Экспорт позиции в FEN (Forsyth–Edwards Notation)

- [ ] Импорт партии из PGN
- [ ] Поддержка вариаций в PGN
- [ ] Расширения для Crazyhouse (карманы в FEN/PGN)

#### 4.2 Дерево ходов (Move Tree)

- [ ] Методы навигации: `goForward()`, `goBack()`, `goToVariation()`
- [ ] Добавление вариаций: `addVariation(move)`

- [ ] Экспорт/импорт дерева в JSON

#### 4.3 Валидатор RuleSet
- [ ] Проверка корректности пользовательских `RuleSet`
- [ ] Детекция бесконечных циклов в генераторах ходов

## 📍 Этап 5: Оптимизация и Продвинутые фичи — 📅 Будущее

**Цель:** Повысить производительность и добавить профессиональные функции.

### Задачи:

#### 5.1 Bitboards (Битовые поля)
- [ ] Представление доски через битовые маски (u64 для 64 клеток)
- [ ] Оптимизированные операции: сдвиги, AND, OR, XOR
- [ ] Быстрая генерация ходов через битовые маски
- [ ] Поддержка для нестандартных досок (опционально)

#### 5.2 Tablebases (Эндшпильные таблицы)
- [ ] Интеграция с Syzygy tablebases
- [ ] Идеальная игра в эндшпилях (до 7 фигур)
- [ ] Кэширование результатов

#### 5.3 Мультиплеер
- [ ] WebSocket сервер для игры по сети
- [ ] Синхронизация состояний между клиентами
- [ ] Комнатная система
- [ ] Рейтинговая система (ELO)

#### 5.4 AI / Bot
- [ ] Простой минимакс с альфа-бета отсечением
- [ ] Оценка позиции (материал, позиция, безопасность короля)
- [ ] Настройка глубины поиска
- [ ] Интеграция с внешними движками через UCI

**Критерии готовности:** Игра по сети с друзьями, бот с настраиваемой силой.
